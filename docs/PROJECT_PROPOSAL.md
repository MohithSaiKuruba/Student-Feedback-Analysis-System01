# Project Proposal: Student Feedback Analysis System

## Problem statement
Institutions collect feedback to understand how students experience courses. Raw feedback can be difficult to compare across courses and may expose personal details if published carelessly.

## Objectives
- Collect anonymous numeric ratings for course questions.
- Store ratings in a normalized MySQL database.
- Calculate course-wise and question-wise average ratings and response counts using Pandas and NumPy.
- Visualize rating distributions and comparisons with Matplotlib.
- Export privacy-conscious aggregate reports.

## Scope and boundaries
**Included:** course catalog, active question catalog, feedback submission, input validation, aggregate dashboard, three charts, CSV export, database health check, tests, and setup/API documentation.

**Excluded:** student accounts, tracking individual students, public display of comments, automated sentiment analysis, and claims about why a rating was given. Demo rows are synthetic. Production use requires institutional approval and appropriate privacy/security review.

## User roles
- **Student/respondent:** submits a course rating and optional comment without a name or student ID.
- **Project demonstrator/administrator:** configures courses/questions in MySQL and reviews aggregate results.
- **Viewer:** sees aggregate metrics only; no raw comments or individual submissions are exposed.

## Features
1. Course feedback form with required 1–5 ratings and optional comment.
2. Flask JSON API for course/question lists and feedback submissions.
3. MySQL foreign keys, rating constraints, and parameterized queries.
4. Pandas group-by summaries and NumPy mean/distribution calculations.
5. Matplotlib charts: rating distribution, average by course, average by question.
6. CSV export with small-group average suppression.
7. Friendly database error messages and test coverage.

## Assumptions and data handling
- One submitted form produces one rating per active question.
- Ratings are ordinal values from 1 to 5; averages are descriptive summaries, not proof of causation.
- A group average is hidden when its response count is below `MIN_GROUP_SIZE`, default 5.
- Comments are optional and stored for future controlled review, but are never displayed in the dashboard/API/export. Respondents are warned not to include personal details.
- A synthetic seed script exists for demo data only. Never commit credentials or real identifiable feedback.

## Analysis methodology
- Validate ratings are in the inclusive range 1–5.
- For each course/question group, compute response count (n) and arithmetic mean (ar{x}=\sum x_i/n).
- Use NumPy for the overall arithmetic mean and Pandas group-by tables.
- Count ratings in each of the five categories for the distribution chart.
- Suppress group means where (n < 5). Small-group counts are shown only as aggregate context in the dashboard; production policy can suppress counts too if needed.

## Limitations
Averages can hide variation and rating scales are ordinal. Synthetic data does not represent actual student opinion. The prototype does not include authentication or a CSRF token and should not be exposed publicly without additional security work. Dashboard chart images are generated at runtime.
